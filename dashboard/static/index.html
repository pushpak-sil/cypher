Syfer

AI-Powered IPsec VPN Protocol Analyzer

Syfer captures live IPsec VPN traffic, identifies how each tunnel is configured — which cipher, DH group, authentication method, and whether Perfect Forward Secrecy is enabled — then uses a machine learning model to infer the type of traffic hidden inside the encrypted tunnel (voice, video, web, email) from side-channel signals like packet sizes and timing. Every session gets a security risk score so analysts can instantly spot weak configurations and prioritize remediation.

How the Pipeline Works

STEP 1

Capture

Intercept IPsec VPN traffic from the network — IKE handshakes and ESP packets.

STEP 2

Protocol Identification

Parse IKE metadata to extract cipher suites, DH groups, PFS, key lifetimes, and auth method.

STEP 3

Traffic Classification

ML model infers what type of traffic is inside the encrypted tunnel from side-channel signals.

STEP 4

Security Scoring

Score each session's security posture on a 0–100 scale based on its configuration.

STEP 5

Report

Generate executive and technical reports with actionable remediation guidance.

IMPORTANT DISTINCTION: PARSED DATA VS. ML INFERENCE
PARSED FROM IKE (NOT AI)

Cipher suite, DH group, PFS status, key lifetime, auth method, and IP version are extracted directly from IKE handshake packets — these are plaintext protocol parameters, not AI predictions.

ML-INFERRED (AI PREDICTION)

The predicted traffic type (VoIP, web, video, etc.) is the genuine ML inference — the model analyzes packet sizes, timing, and flow patterns to classify what's inside the encrypted tunnel.

Metric Glossary

Risk Score (0–100)

A composite score reflecting the overall strength of a VPN session's cryptographic configuration. Higher is better.

Why it matters: Instantly tells you whether a tunnel is well-configured or dangerously weak — without reading every parameter yourself.

Threat Matrix

Per-category risk assessment across four dimensions: Cryptographic Strength, Key Management, Replay Protection, and Metadata Exposure. Each rated Low / Medium / High.

Why it matters: Pinpoints exactly which aspect of a session's security is weak, so remediation can be targeted.

AI Confidence Score

How confident the ML model is in its traffic-type prediction, expressed as a percentage (0–100%).

Why it matters: Low confidence means the model isn't sure — the analyst should treat that prediction with skepticism.

Cipher

The encryption algorithm used to protect tunnel traffic (e.g., AES-256-GCM, 3DES-CBC).

Why it matters: Weak ciphers like 3DES are vulnerable to brute-force attacks — modern tunnels should use AES-256-GCM or ChaCha20.

DH Group

The Diffie-Hellman group used for key exchange. Higher groups use longer keys or elliptic curves.

Why it matters: A weak DH group (e.g., Group 2 — 1024-bit) can be cracked, compromising the entire session.

Perfect Forward Secrecy (PFS)

When enabled, each session uses a unique key — compromising one key doesn't reveal past or future traffic.

Why it matters: Without PFS, a single key compromise can decrypt all historical traffic.

Key Lifetime

How long a session key is valid before renegotiation (in seconds).

Why it matters: Shorter lifetimes limit exposure if a key is compromised. Lifetimes over 12 hours are considered risky.

Predicted Traffic Type

What the ML model thinks is running inside the encrypted tunnel — VoIP, web browsing, video, email, ICMP, or file transfer.

Why it matters: Knowing the traffic type helps assess whether the tunnel's security level is appropriate for the data it carries.
